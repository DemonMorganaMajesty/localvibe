# CACHE_REBUILD_EXECUTOR 线程池
```java
public static final ExecutorService CACHE_REBUILD_EXECUTOR
        =Executors.newFixedThreadPool(10);
```
> 在**逻辑过期方案解决缓存击穿**这里使用：缓存发现过期，不阻塞用户请求，提交任务到线程池做缓存重建，**主线直接返回旧缓存数据**。

## 线程池在这里带来的好处（结合你的业务场景讲，面试重点）
### 1. 异步执行缓存重建，用户请求不用等待重建，接口响应快
如果不使用线程池，缓存重建（查数据库、序列化、写Redis）就要在用户的http请求线程里面执行。
- 重建耗时200ms，用户接口就要卡住200ms才返回。
- 使用线程池：把重建任务丢给后台线程去做，**http主线立刻返回旧的Shop数据给前端**，用户几乎无等待。

> 逻辑过期核心特点：**即使缓存过期，也永远返回旧数据，异步后台更新缓存，不会阻塞用户**。

### 2. 控制并发重建数量，防止大量线程同时打数据库
`newFixedThreadPool(10)` 固定10个工作线程。
热点key大量同时过期，会触发大量缓存重建任务。
- 如果不用线程池，直接`new Thread()`新建线程：瞬间创建几百上千线程，线程爆炸，耗尽服务器CPU、内存，大量并发请求同时访问MySQL，直接打崩数据库。
- FixedThreadPool最多同时10个线程干活，多余任务进入队列排队，**限制同时重建缓存的并发数，保护数据库**。

### 3. 线程复用，避免频繁创建销毁线程开销
创建Java线程成本很高：操作系统要分配栈内存、内核资源。
- 每次缓存重建都new Thread：任务多就频繁创建销毁线程，开销大。
- 线程池里面10个线程反复复用，任务来了直接拿已有线程执行，减少系统开销。

### 4. 任务队列缓冲，削峰
短时间大量缓存重建任务过来，超过10个活跃线程，任务会进入阻塞队列排队，不会直接拒绝或者疯狂新建线程，起到削峰效果。

### 5. 便于统一管理，后续可以监控、拒绝策略
ExecutorService统一管理一批后台任务；可以统计任务数量、关闭线程池、设置拒绝策略。

## 结合你的代码看调用位置
```java
//缓存过期了，拿到锁，提交任务到线程池
CACHE_REBUILD_EXECUTOR.submit(()->{
    try {
        this.saveShopWithLogicExpireTime(id,30L);
    } catch (Exception e) {
        throw new RuntimeException(e);
    } finally {
        unlock(lockKey);
    }
});
//主线直接return shop，不等待这个线程执行完毕
return shop;
```
> 关键点：**submit是提交，不会阻塞等待任务执行完成。主线直接返回旧数据。**

## ⚠️当前代码的缺陷（面试主动说，体现思考深度）
1. `Executors.newFixedThreadPool(10)`底层默认队列是 `LinkedBlockingQueue`，**无界队列**。
   极端情况：几万缓存重建任务涌入，任务全部堆积队列，内存越堆越大，OOM风险。
> 阿里开发手册禁止直接用Executors工厂方法，建议手动`ThreadPoolExecutor`构造，指定队列容量+拒绝策略。

2. 静态线程池，Spring容器关闭的时候没有优雅关闭，程序关闭会丢失正在执行的缓存重建任务。可以增加`@PreDestroy`钩子调用`shutdown()`。

3. 任务内部catch处理简单，任务异常直接抛RuntimeException，没有日志打印，线上排查问题困难。

### 面试口述版本
> 在逻辑过期解决缓存击穿场景，我使用线程池异步做缓存重建。
> 当检测缓存逻辑过期，拿到互斥锁之后，把重建任务提交线程池，HTTP请求主线直接返回过期的旧缓存数据，保证接口响应速度，用户不用等待数据库查询。
> 使用FixedThreadPool固定线程数，限制同时执行缓存重建的并发数量，避免热点key过期瞬间大量线程同时访问MySQL，保护数据库；同时线程复用，避免频繁创建销毁线程带来的系统开销。
> 缺点：直接使用Executors工具类创建，队列无界，存在OOM风险，生产建议手动构造ThreadPoolExecutor，指定有界队列和拒绝策略；并且要增加容器销毁时线程池优雅关闭逻辑。

## 补充区分两种缓存击穿方案
1. **互斥锁 selectWithMutex**：同步，用户线程自己做缓存重建，用户需要等待；会阻塞，无旧数据返回。
2. **逻辑过期 + 线程池异步重建 selectWithLogicExpire**：不阻塞用户，返回旧数据，后台线程池更新缓存；**数据会短暂不一致**。
